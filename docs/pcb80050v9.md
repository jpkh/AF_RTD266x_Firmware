# PCB80050V9 — RTD2660H bench board

EastRising-style generic display board. This is the main development board
for the jDronics RTD2660H project.

## Hardware

| Item | Value |
|---|---|
| Board | PCB80050V9 (generic RTD2660H controller) |
| Controller | Realtek RTD2660H (DW8051 core) |
| Flash | Zetta ZD25Q40, JEDEC `5E6013`, 4 Mbit = 512 KiB |
| Panel | ER-TFT043A3-3, 4.3" 480x272, 24-bit TTL RGB, 1000 cd/m² (panel driver ST7282 — irrelevant to firmware) |
| Inputs on board | 2× CVBS/AV, 1× VGA, 5-key keyboard (HDMI appears in firmware source lists but is not fitted) |

Two identical boards were used for validation: board1 (panel + keyboard
attached) and board2 (bare).

## Feather wiring (direct ISP + DDC bus)

Feather RP2350 HSTX (USB serial `25E37696B8051E25`, usually COM23):

| Feather | Board | Signal |
|---|---|---|
| GPIO4 | VGA connector P12 | DDC1 SDA |
| GPIO5 | VGA connector P15 | DDC1 SCL |
| GND | VGA connector P10 | ground |

Pull-ups: 10k to Feather 3.3 V (the board adds its own in parallel; 10k is
fine at the 100 kHz ISP speed). Do not connect to a 5 V rail.

RTD2660H pin mapping: pin 59 = TXD/DDC1_SCA/P3D1 (SDA), pin 58 =
RXD/DDC1_SCL/P3D0 (SCL). The VGA DDC pins, the ISP interface and the
DDC/CI slave share this bus — that is why one scan shows `0x37` (DDC/CI),
`0x4A`/`0x4B` (ISP) and `0x50` (EDID emulation).

## Programmer / host

- Sketch: `tools/tester/feather_rp2350/Feather_HSTX_RTD_Tester`
- Host CLI: `tools/tester/feather_rp2040/Feather_DVI_RTD_Tester/host.py`
- Direct bus commands: add `--bus gpio` (ISP *and* DDC/CI/EDID follow the
  selected bus); default `--bus ddc` is the HDMI-adapter path.
- Compile with the documented `arduino-cli` command plus
  `--build-property "compiler.cpp.extra_flags=-I<sketchdir>"`.

| File | Board | SHA256 |

| `zd25q40_board2.bin` | board2, original stock firmware | `9866fcb9f7b4bb2a8749fc8a3aae305efd90cbb21edef08c4a95fed894bbabe8` |
| `zd25q40_board1_preflash.bin` | board1 before 480x272 flash | `3ccfb40615ffb37977c15dcb88fa42e35ae683c6ca3254d85d7340e5ed08c79e` |

Verified facts:

- Board1 and board2 code regions (0x00000-0x3FFFF) are byte-identical; only
  ~462 bytes of vendor config differ (0x040007-0x04554F).
- **The stock firmware writes runtime state to flash while running**: the
  header at `0x40000-0x400FF` and a settings blob at `0x45550-0x4559F` change
  during use (no settings EEPROM on this board). The host preflight
  ("current matches backup or target") therefore fails on a used board;
  programming requires either a fresh dump used as backup, or the
  `--recover` path with the target as both image and backup.
- All dumps used two independent full reads; every 256-byte block was
  checked against the RTD hardware CRC.

## Installed test firmware

- Source: `RTD2660_PCB800099` collection,
  `Firmware\PCB80009\PCB80009 pcb800100-ttl-480x272-4,3inch-at043tn24v.1-2av1vga-1hdmi-5key-ir2.bin`
  (256 KiB; TTL RGB, 480x272, 4.3" AT043TN24 profile, 2AV + 1VGA + 1HDMI,
  5-key).
- Flashed target: `zd25q40_board1_480x272_v2.bin` = candidate + board1 tail
  from `0x40000` (vendor config preserved). Receipt: `*.program-*.json`.
- Verified working on board1: full-screen OSD, AV2 camera feed, key handling.
  AV1 untested (no source connected), HDMI listed but not wired.

## DDC/CI status on stock firmware

- EDID emulation at `0x50` works (RTK, "Monitor", valid checksums) — read
  with `host.py --bus gpio edid out.bin`.
- `0x37` ACKs, but the stock firmware does not answer standard VCP frames;
  it echoes request bytes back (`vcp-get` fails with a checksum mismatch).
  Brightness/contrast/source control over DDC/CI will work with the
  Adafruit-derived firmware, which implements the protocol (`vcp-get 0x10`,
  `vcp-set 0x10 <n>`, `key`, `menu-state`).
